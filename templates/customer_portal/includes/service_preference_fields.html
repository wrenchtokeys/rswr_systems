{% comment %} "When works for you, and where will the vehicle be?" (FIELD_OPS S4). Shared by the repair request page and the replacement request page so the two never drift. Everything here is optional — a customer who just wants the work done submits exactly as before. Both forms post these field names: `preferred_date`, `preferred_window`, and the four `service_*` address fields. The replacement page posts them natively as part of its
; the repair page is JS-driven (units are assembled into one FormData in static/js/customer_repair_request.js), so it reads the same names out of the DOM. One card, one set of names, one server-side reader — apps/customer_portal/views._read_service_preference. The address inputs start EMPTY behind a toggle rather than prefilled with the customer's address on file. Prefilling would mean every request froze a copy of the company address as it stood that day, so fixing a typo on the customer record would fix nothing anywhere (S2 hit this and solved it by blanking an unchanged prefill — starting empty avoids the problem instead of undoing it). The server still normalizes and drops an override that matches. {% endcomment %}
